# 语义评测

`semantic-cases.json` 保存 Java 后端质量规则的代表性决策场景。它用于检查 Agent 是否做出了正确判断，不要求固定措辞，也不替代真实项目中的源码、契约和测试。

每个用例包含：

- `fixture`：提供给 Agent 的最小代码或任务背景
- `expected_decisions`：回答中必须体现的判断
- `disallowed_decisions`：不能出现的错误判断
- `triggers`：该场景应加载的详细规则

建议使用没有继承原讨论结论的新会话或独立评测者，将 Skill、单个 fixture 和“只给出审查或实现决策”的任务交给它。评测者按含义判断是否覆盖所有期望决策，而不是比较原句。编码循环场景应特别记录任务是简单还是复杂、何时触发阶段检查、何时因新边界升级，以及是否在语义不确定时暂停。发现失败后先修正规则，再重新运行全部受影响用例。

注释文案场景要求评测者给出具体改写或保留理由，再逐项检查：是否说清对象和动作、是否保留原有条件和保证、是否编造原因，以及必需的 JavaDoc、校验簇和 catch 说明是否仍在。领域术语和真实因果句可以保留，不按固定句式或词语黑名单评分。记录改写原文及判断依据，不把“建议文案更自然”当作已经完成文案验证。

资料校准场景覆盖方法职责、日期区间与开关包装、快照读取时点、状态名称、独立常量与结构数字、循环与 Stream、借用和自有资源、关闭异常、超时结果不确定及多层重试。记录具体保留或调整方案及行为依据；不因答案提到了书名或设计术语就判通过。阶段检查仍要执行，但不要求每个清楚的调用都新增正文注释。

下面的命令只校验评测文件结构，不运行模型，也不能证明语义行为正确：

```powershell
py -3 scripts/validate_semantic_evals.py evals/semantic-cases.json
```
